<task type="auto">
  <name>Task 1: Clean install dependencies and run production build</name>
  <files>package-lock.json, node_modules/ (not committed), build/</files>
  <action>
    Run the following commands in sequence from the plugin root. Each must succeed before proceeding.

    Step 1 — Remove old conflicting packages (node-sass uses native bindings that conflict on Node 18+):
    ```bash
    npm uninstall node-sass gulp csso-cli
    ```

    Step 2 — Delete node_modules to ensure a clean slate (avoids native binding conflicts from old installs):
    ```bash
    rm -rf node_modules
    ```

    Step 3 — Fresh install with the updated package.json:
    ```bash
    npm install
    ```
    Expected: No node-gyp rebuild errors. If errors appear about native bindings, they are from node-sass which should no longer be in package.json — double-check package.json was updated correctly in Plan 01.

    Step 4 — Run the production build:
    ```bash
    npm run build
    ```
    Expected: webpack outputs files to build/. The build will emit a notice about `build/frontend/style.js` being an empty JS file — this is EXPECTED behavior (Pitfall 2 from research) and can be ignored. Do not add webpack-remove-empty-scripts to suppress it.

    If `npm run build` fails, check:
    - Is `src/admin/index.js` present? (Plan 02 prerequisite)
    - Is `src/frontend/style.scss` present? (Plan 02 prerequisite)
    - Does `webpack.config.js` use `defaultConfig.entry()` with parentheses? (Plan 01)
  </action>
  <verify>
    1. `ls build/admin/` — should contain at minimum: `index.css`, `index.js`, `index.asset.php`
    2. `ls build/frontend/` — should contain at minimum: `style.css`, `style.js` (empty JS is expected)
    3. `npm run build` exit code is 0 (no errors)
  </verify>
  <done>npm install completes without node-gyp errors. npm run build exits 0 and produces build/admin/index.{css,js,asset.php} and build/frontend/style.css at minimum.</done>
