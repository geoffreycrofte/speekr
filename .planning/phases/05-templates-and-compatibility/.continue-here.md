### Bug 1 — wp_editor('content') breaks Gutenberg content saving (BLOCKER)
File: inc/admin/custom-meta-boxes.php, function speekr_the_content_mb() (~line 264)
Root cause: wp_editor( $content, 'content', $settings ) uses 'content' as editor ID,
which hijacks Gutenberg's main post content field → Gutenberg autosave broken.
Fix: This entire meta box (speekr-content / speekr_the_content_mb) should be REMOVED
for block editor context. The post content is natively handled by Gutenberg.
Register meta box with __back_compat_meta_box => true so it only shows in classic editor.
OR: remove the wp_editor call and keep only the checkbox, let Gutenberg handle content.

<context>
The meta box that causes the content saving issue is registered WITHOUT __back_compat_meta_box => true (unlike the other 3 meta boxes). This means it shows in Gutenberg AND the classic editor. The wp_editor( $content, 'content', ... ) call — using the literal string 'content' as the editor ID — replaces Gutenberg's native content editor with a TinyMCE instance, which then doesn't hook into Gutenberg's save mechanism.

The fix for Bug 1: add __back_compat_meta_box => true to the 'speekr-content' add_meta_box call so it only shows in classic editor. Or remove the entire meta box since Gutenberg natively handles post content.

The fix for Bug 2: invert all $is_blog checks. The meta key 'speekr-as-article' stays the same key name but semantics flip: 'on' will now mean "reference only" (NOT a blog post). The checkbox label changes from "Make this Speekr item a blog post" to something like "Reference only — hide post content and permalink".
</context>
